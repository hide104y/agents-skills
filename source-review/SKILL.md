# Java 7 ソースコードレビュー＆改善スキル

指定された対象パス配下のJavaソースコードをレビューし、Java 1.7 (Java 7) への最適化、単体テストコード作成、およびJavadocコメントの整備を段階的に実施する手順書です。

## 適用前提および対象スコープ（ガードレール）

1. **レビュー・修正対象スコープ**:
   - `src` ディレクトリ配下のうち、**`src/main/java/tool` 配下のファイルのみ** をレビュー、修正、および単体テストの対象とします。
   - `src/main/java/tool` 以外のディレクトリ（例: `src/main/java/org` など）は **編集・変更禁止** です。
2. **ファイルシステム保護（上位ディレクトリへの影響禁止）**:
   - カレントディレクトリより上位のディレクトリには絶対に影響を与えないこと。
   - 単体テスト等でディレクトリやファイルの作成・削除が必要な場合は、システムの一時ディレクトリ配下に以下の規則で作業ディレクトリを構築し、その配下でのみ操作を行うこと。
     ```java
     // 一時作業ディレクトリの生成例（Java 7）
     Path tempDir = Paths.get(System.getProperty("java.io.tmpdir"), "UnitTest", "{projectName}", "{className}");
     ```
   - テスト完了後は作成した一時ファイルを確実にクリーンアップすること。
3. **対話型進行（Human-in-the-Loop）**:
   - 以下のタスクは必ず **1ステップずつ順番に実行** すること。
   - **各タスクの完了時にユーザーへ結果を報告し、承認（確認）を得てから次のタスクへ進むこと**。一括で実行してはならない。

---

## 実行タスク手順

### タスク1: Java 1.7 最適化レビュー・修正およびAntビルド検証
1. **Java 1.7 (Java 7) 言語仕様への最適化**:
   - 対象ソースコードを精査し、Java 7 の構文・APIを活用して可読性・安全性を向上させる：
     - **try-with-resources** による確実なリソース（Stream, Connection等）の自動クローズ
     - **ダイヤモンド演算子 (`<>`)** による型推論の簡潔化
     - **マルチキャッチ (multi-catch)** による重複例外処理の集約
     - **文字列による switch 文** の適用
     - **NIO.2 (`java.nio.file.Path`, `Paths`, `Files`)** の活用
   - **重要**: Java 8 以降の機能（ラムダ式、Stream API、`java.time`、`Optional` 等）は使用せず、Java 7 実行環境との完全な互換性を維持すること。
2. **Ant ビルド設定 (`build.xml`) の検証・修正**:
   - プロジェクトが Apache Ant でビルド可能であることを確認する。
   - 必要に応じて `build.xml` 内のコンパイラ設定（`source="1.7"`, `target="1.7"`）やクラスパス設定を適切に更新・修正する。
3. **確認と承認**:
   - 修正内容とビルド結果をユーザーに提示し、承認を得ること。

### タスク2: 単体テストプロジェクトおよびテストコードの作成
1. **テスト構成の整備**:
   - 対象クラスに対応する単体テストコードを作成する。
   - テストプロジェクトまたはテスト用ソースディレクトリ（例: `src/test/java` 等のプロジェクト規約に準拠した構成）に配置する。
2. **テストコードの実装**:
   - 正常系・異常系・境界値のテストケースを網羅する。
   - ファイル/I/O操作を伴うテストは、前提条件で定めた一時ディレクトリ（`java.io.tmpdir/UnitTest/...`）を使用し、上位ディレクトリやプロジェクト本体のファイル環境を破壊しないこと。
   - テスト終了時の自動クリーンアップ（JUnitの `@Rule TemporaryFolder` または `@After` 処理等）を実装すること。
3. **確認と承認**:
   - 作成したテストコードとテスト実行結果（Ant経由のテスト実行等）をユーザーに報告し、承認を得ること。

### タスク3: Javadoc コメントの作成・整備
1. **クラスレベル Javadoc**:
   - クラスの役割、設計概要、および一般的な利用用途を明確に記述する。
   - 必要に応じて `@author`, `@version`, `@since` などの標準タグを記載する。
2. **メソッドレベル Javadoc**:
   - メソッドの概要説明、処理内容を明確に記述する。
   - 全引数に対する `@param`、戻り値に対する `@return`、スローされる例外に対する `@throws` を漏れなく記述する。
   - 主要なメソッドには `<pre>{@code ... }</pre>` を用いた具体的な使用例（コードスニペット）を付与する。
   - **注**: 既存のコメントが不完全または古い場合は、最新の実装に合わせて上書き・更新すること。
3. **確認と承認**:
   - 整備した Javadoc の内容をユーザーに提示し、最終承認を得ること。
